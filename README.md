# BuildFlow

Небольшая CRM строительной компании: объекты, задачи на них, проверка менеджером. React + TypeScript + Supabase.

Правила доступа и смены статусов проверяет сама база данных (Row Level Security и триггеры), а не только интерфейс. Даже прямой запрос к API Supabase в обход приложения не позволит увидеть чужое, сделать запрещённый переход или подделать историю.

- Объяснение для менеджера без технических деталей: [docs/EXPLANATION.md](docs/EXPLANATION.md)
- Принятые решения и допущения, что не сделано: [docs/DECISIONS.md](docs/DECISIONS.md)

## Что умеет

| | Менеджер | Исполнитель |
|---|---|---|
| Видит | всё | только свои задачи и объекты, где они есть |
| Объекты | создаёт, меняет, удаляет (в корзину) | только смотрит |
| Задачи | создаёт, меняет, назначает исполнителя, удаляет (в корзину) | только меняет статус |
| Статусы | принимает или возвращает на доработку (комментарий обязателен) | берёт в работу, отправляет на проверку |
| Фото | добавляет и удаляет | добавляет, пока задача в работе или на доработке |
| Остальное | фильтры, выгрузка в Excel, корзина, очередь проверки | экран «Мои задачи» |

Допустимые переходы статусов:

```
Новая → В работе → На проверке → Принята
                       ↓
              Нужна доработка → В работе
```

Каждая смена статуса записывается в историю: кто, когда, из какого статуса в какой и комментарий.

## Демо-доступ

Приложение: https://build-flow-code-gen.vercel.app

Тестовые пользователи (создаются файлом `supabase/seed.sql`):

| Роль | Почта | Пароль |
|---|---|---|
| Менеджер | manager1@example.com | Demo-Manager-1 |
| Менеджер | manager2@example.com | Demo-Manager-2 |
| Исполнитель | executor1@example.com | Demo-Executor-1 |
| Исполнитель | executor2@example.com | Demo-Executor-2 |

Открытая регистрация отключена. Новых пользователей создаёт администратор в Supabase (Authentication → Users) и добавляет им строку в таблицу `profiles` с ролью.

## Запуск

Нужны Node.js 20+ и бесплатный проект Supabase.

1. Создайте проект в Supabase. В Authentication → Sign In / Providers выключите «Allow new users to sign up».
2. В SQL Editor по порядку выполните файлы из `supabase/migrations/` (семь файлов), затем `supabase/seed.sql` (один раз). Это создаст таблицы, правила, фото-хранилище и демо-данные. Если база уже создана, выполните только новые файлы миграций по порядку.
3. Скопируйте `.env.example` в `.env` и впишите адрес проекта и публичный ключ (Settings → API Keys, ключ `sb_publishable_...`).
4. Запуск:

```bash
npm install
npm run dev
```

Секретный ключ (`service_role` или `secret`) приложению не нужен и в репозиторий не попадает. Публичный ключ по замыслу виден в браузере: безопасность держится на правилах базы.

## Проверка защиты

Скрипт заходит под разными пользователями и пробует запрещённое напрямую через API (чужие задачи, запрещённые переходы, правка истории, загрузка файлов в чужие задачи и другое):

```bash
npm run check:rights
```

Ожидаемый результат: все строки `OK`, в конце «Все проверки прошли». Скрипт работает около двух минут и создаёт одну временную задачу, которая остаётся в корзине менеджера.

## Автотесты

```bash
npm test            # логика (статусы, страницы, выгрузка в Excel): без сети, меньше секунды
npm run test:e2e    # интерфейс в Chrome: около 20 секунд
```

Проверки интерфейса идут на локальном сервере (`npm run dev` поднимается сам) и используют установленный Chrome. Списки, фильтры, страницы и роли проверяются на заглушке Supabase (`e2e/mock.ts`): сети и входа не нужно. В настоящий Supabase из `.env` ходят два теста: неверный пароль и полный путь задачи по ролям (создание, правка, работа, возврат, принятие, корзина). Второй оставляет одну задачу «UI-тест …» в корзине менеджера. Очистка в SQL Editor: `delete from public.tasks where title like 'UI-тест%' or title like 'Проверка прав%'`.

## Структура

```
supabase/migrations/   таблицы, правила доступа, триггеры, корзина, фото, закрытая схема, журнал полей, счётчики, защита от удалённого объекта
supabase/seed.sql      демо-пользователи, объекты и задачи
scripts/check-rights.mjs   проверка защиты через API
e2e/                   автотесты интерфейса (Playwright)
src/                   приложение (страницы, компоненты, работа со статусами)
```

## Технологии

React 19, TypeScript, Vite, React Router, supabase-js. Без UI-библиотеки: стили написаны вручную, есть светлая и тёмная тема.
