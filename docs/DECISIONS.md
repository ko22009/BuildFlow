# Решения, допущения и что не сделано

## Где задание допускало разное понимание

| Вопрос | Решение | Почему |
|---|---|---|
| Видит ли исполнитель объект, где все его задачи приняты? | Да, пока есть хотя бы одна его задача, в том числе принятая | Так принято в полевых системах, проще правило доступа, история работы не пропадает |
| Кто и когда может сменить исполнителя? | Менеджер, только пока задача «Новая» или «Нужна доработка» | У задачи в работе или на проверке исполнитель не меняется, история остаётся честной |
| Что значит «удалить» объект или задачу? | Перенос в корзину, менеджер может восстановить. Настоящее удаление через API запрещено | Требование «историю нельзя удалить» выполняется полностью, ошибочное удаление не страшно |
| Можно ли удалить объект с задачами? | Нет, сначала задачи в корзину | Защита от потери данных |
| Менеджер может быть исполнителем? | Нет, исполнитель назначается только из пользователей с ролью «исполнитель» | Роли не пересекаются, меньше случаев для проверки |
| Может ли менеджер сам менять статус за исполнителя? | Нет, только переходы из задания | В задании остальные переходы запрещены |
| Комментарий при возврате на доработку | Обязателен, не из пробелов. Проверяет база, а не только форма | Требование безопасности должно работать без интерфейса |
| Комментарий при других переходах | Необязательный, сохраняется в истории | Бесплатное улучшение: поле уже есть в журнале |
| Автор задачи | Ставит база из текущего пользователя | Иначе поле теряет смысл |
| Запись о создании задачи в истории | Есть (из «ничего» в «Новая») | Полная картина жизни задачи |
| Формат объяснения для менеджера | Текст `docs/EXPLANATION.md` | Допускается заданием (вместо видео) |
| Хранение времени | UTC в базе, в интерфейсе по часовому поясу браузера | Стандартный подход |

## Что добавлено сверх задания

Срок исполнения и метка «просрочено», счётчики по статусам на объекте, очередь «Ждут проверки», фильтры (статус, объект, исполнитель) с сохранением в адресе страницы, выгрузка в Excel (.xlsx, библиотека write-excel-file, ширина столбцов и настоящие даты), фото к задачам в закрытом хранилище, корзина, необязательный комментарий при любом переходе, автоматическая проверка прав (`npm run check:rights`), светлая и тёмная тема.

## Что не сделано и почему

- **Уведомления о смене статуса** (в мессенджер MAX): отложено на будущее. Потребуется бот и Edge Function.
- **Интеграции с 1С, чертежи, финансы, портал заказчика**: вне объёма.
- **Восстановление пароля и приглашения по почте**: пользователей создаёт администратор вручную, как требует задание.
- **Корзина не разбита на страницы**: в ней только удалённое, объём небольшой. Остальные списки (объекты, задачи, задачи объекта) загружаются по 20 штук.

## Безопасность: что проверено и что осталось

- Security Advisor в Supabase: 0 ошибок, 1 предупреждение «Leaked password protection disabled». Это платная опция Auth (проверка паролей по базам утечек). Регистрации нет, пароли задаёт администратор, поэтому оставлено как есть.
- Служебная функция `app_role` вынесена в закрытую схему `private` (миграция 5): через API её вызвать нельзя.
- В репозитории нет секретных ключей. Публичный ключ Supabase по замыслу виден в браузере и в репозиторий не коммитится: он задаётся переменными окружения (`.env` локально, Environment Variables на Vercel).
- Регистрация отключена в настройках Auth (проверка: публичный запрос к `/auth/v1/settings` возвращает `disable_signup: true`).

## Добавлено после первой сдачи

- **Журнал изменений полей** (название, описание, срок, объект, исполнитель): таблица `task_changes`, пишет триггер, через API только чтение (миграция 6). Объект и исполнитель хранятся именем на момент изменения.
- **Постраничная загрузка**: списки по 20 строк, номер страницы в адресе (`?page=2`). Фильтры, порядок «Моих задач» и счётчик «Ждут проверки» считает база; счётчики по статусам на карточках объектов считает функция `object_task_stats`. Выгрузка в Excel забирает все подходящие задачи частями по 1000.
- **Автотесты**: `npm test` (логика) и `npm run test:e2e` (интерфейс в Chrome, в основном на заглушке Supabase). Защита через API по-прежнему проверяется `npm run check:rights`.
- **Защита от задачи в удалённом объекте** (миграция 7): активную задачу нельзя перевести в объект из корзины ни через интерфейс, ни прямым запросом к API. Просрочка и счётчики считаются по местной дате браузера: у пользователя свой часовой пояс, и UTC-дата до 05:00 в Екатеринбурге давала вчерашний день.

## Упрощения с известным пределом

- Демо-пароли лежат в `supabase/seed.sql` и README. Это тестовые данные для проверки задания, в рабочей системе так не делают.
- Проверочный скрипт оставляет одну временную задачу в корзине менеджера за запуск (настоящее удаление запрещено). Корзину можно очистить SQL-запросом администратора. Так же ведёт себя тест интерфейса (задачи «UI-тест …»).
